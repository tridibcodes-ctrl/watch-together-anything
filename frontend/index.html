    Video source and playback options

    Use the video’s play, pause and seek controls to control both screens. Volume and subtitles are yours to choose. If prompted, press Play once to let your browser load the video. Playback waits until both people are ready.

    Having trouble? Try the reload icon, or choose another source below. Changing source affects both screens and keeps the room’s position. Pick episodes in the app so you stay on the same episode.

    Backend contract

    Authenticated API calls should send the Supabase access token as a Bearer token. The backend must still enforce room membership and permissions. Keep secret keys out of this file.

    GET /api/me
  → {profile:{userId,displayName,avatarKey},groupId,roomId}
GET /api/catalog?type=movie&page=1
GET /api/search?type=movie&q=...&page=1
  → {items:[{tmdbId,mediaType,title,year,overview,posterPath}],page,hasMore}
GET /api/titles/{movie|tv}/{tmdbId}
  → {title:{tmdbId,mediaType,title,year,overview,posterPath,genres,runtimeMinutes,status,seasons}}
GET /api/titles/tv/{tmdbId}/seasons/{seasonNumber}
  → {tmdbId,mediaType,seasonNumber,name,episodes:[{episodeNumber,name,overview,airDate,runtimeMinutes}]}
GET /api/rooms/{roomId}/list
  → {items:[{id,title:{tmdbId,mediaType,title,year,overview},status}]}
POST /api/rooms/{roomId}/list ← {mediaType,tmdbId} → {item}
DELETE /api/rooms/{roomId}/list/{itemId} → 204
PATCH /api/me/profile ← {displayName,avatarKey} → {profile}

GET /api/rooms/{id}/state
// Join/Leave playback are local opt-in actions.
POST /api/rooms/{id}/media ← {commandId,expectedRevision,mediaType,tmdbId,season?,episode?}
POST /api/rooms/{id}/commands
  ← {commandId,expectedRevision,sessionId,action:"play"|"pause"|"seek"|"provider",targetPositionMs?,provider?}
  → {roomId,sessionId,media:{mediaType,tmdbId,title,season?,episode?},
     provider,status,positionMs,anchorAt,revision,serverTime}
  // An empty room has sessionId:null and media:null.
  // Each state-producing route above returns this same room snapshot.
// Leaving playback does not remove room membership.

GET /api/rooms/{id}/messages → {items:[{id,senderName,body,createdAt}]}
POST /api/rooms/{id}/messages ← {clientMessageId,body} → {message}
// Planned (not implemented):
POST /api/sessions/{id}/complete ← {commandId,confirmed:true}
  → {completed,message}
POST /api/sessions/{id}/undo-completion ← {commandId} → {completed:false}

Errors: {error:string}; playback conflict: {error:string,state} with an appropriate HTTP status.
Positions are milliseconds; timestamps are ISO UTC; TMDB IDs are numbers.
Shared-list status: planned | watching | watched.
Serialize playback commands and deduplicate UUIDs on the backend.
Completion must verify both users' confirmations; one request is not proof.
TV completion applies to an episode, not automatically the entire series.

    Room playback and chat use authenticated live updates with automatic checks for missed updates. Completion tracking remains planned.
